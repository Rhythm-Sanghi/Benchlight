## Changes and safety evidence

Cleanup creation now commits the database row and its matching JSON id together.
Each staging and final-result transition commits the plan detail and operation
event together. An injected SQLite log failure rolls both writes back. A
disposable interrupted-staging test reopens the database before and after a
fixture rename and confirms that neither state can be applied again. Existing
fixture tests still cover exact confirmation, locks, changed evidence, junctions,
directory replacement and successful recycling. The desktop refreshes persisted
state after an apply error and shows the original and recovery locations without
claiming an uncertain recycle succeeded. Windows Recycle Bin operation itself
is not an atomic transaction with SQLite.

Directory enumeration now rechecks exact entry membership with a bounded name
set before reporting a complete measurement. The original moving-directory
test and a deterministic unchanged-timestamp membership test pass. This remains
a point-in-time filesystem observation rather than an atomic snapshot.

Working-history count and approximate stored JSON bytes are shown per project.
Older records require exact typed confirmation and an unchanged record count;
the latest baseline is retained. Database and reopened-core tests cover this
behavior. There is no schema change or silent retention policy. The size figure
is not predicted SQLite file-space recovery.

The Tools screen now states that an explicit refresh launches bounded native
version commands without sandboxing. Existing process tests cover timeouts and
output limits; executable behavior beyond that boundary is not certified.

## Release qualification

The source archive is generated by `git archive` from one resolved commit or
tag. The script checks committed package/Tauri versions, license and third-party
notice inventory, refuses known sensitive/local-data paths and existing output,
and emits a commit/tree/hash manifest. A disposable Git fixture verifies
untracked-file exclusion, dirty working-tree exclusion, legal-file inclusion,
repeatable hashes and refusal of a committed sensitive path. Publishing now
requires the release tag to identify the checkout commit and includes the
manifest in SHA-256 sums. It was not invoked.

Windows workflows retain read-only permission for ordinary checks. Action
revisions, Rust 1.98.1 and Node 24.15.0 are pinned; lockfiles remain in use.
The hosted Windows image and package availability can still vary. CI has not
run on these local commits.

On this host, `scripts/check.ps1` passed Rust formatting, clippy and workspace
tests (three internal process fixtures intentionally ignored), the source
archive regression, 80 contrast pairs, 23 frontend tests, formatting, lint,
typecheck and production frontend build. `npm run tauri build` produced the
Windows NSIS bundle. `scripts/test-installer.ps1 -RunId oct15-hardening`
passed isolated install, fixture CLI scan, same-version reinstall, uninstall
and metadata preservation. The test refused to reuse earlier fixture paths.
Manual desktop startup, offline operation and different-version upgrade remain
NOT VERIFIED.

Three optimized benchmark runs used fresh 50-project / 20,050-file temporary
fixtures. Scan times were 1,949, 2,183 and 1,297 ms; 100-page query times were
30, 117 and 26 ms; cancellation times were 7, 6 and 1 ms, all returning
`cancelled`. Sampled process peaks were 9,379,840, 7,933,952 and 8,011,776
bytes. See [benchmarks](benchmarks.md) for methodology. Run variation and
different load prevent a speedup claim against the older single run.
